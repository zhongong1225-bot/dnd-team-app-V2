# 主动释放功能 — 交互逻辑

> 更新日期：2026-09-04
> 基于代码实际行为整理，按"原生地/映射地"框架组织
> 布局规范参考：[CARD_LAYOUT_SPEC.md](./CARD_LAYOUT_SPEC.md)

## 一、两个入口位置

### 原生地 — 卡片自带的"使用"按钮

所有卡片共用 6 列网格系统（固定高度 52px），按钮在特性区（第3列）居中显示。
种族/职业/专长用窄卡网格（特性区 270px），装备用标准网格（特性区 360px）。

| 卡片类型 | 按钮样式 | 说明 |
|---------|---------|------|
| 职业特性卡 | 名称+⚡使用 一体按钮 | 金色边框，min-width 200px，居中显示 |
| 种族特性卡 | 名称+⚡使用 一体按钮 | 同职业样式，居中显示 |
| 专长卡 | 名称+⚡使用 一体按钮 | 同职业样式，居中显示 |
| 装备卡 | 能量条一体按钮 | 整个按钮就是能量条，背景显示充能进度（金色=满，橙色=低），名称+使用+步进器叠在上面 |
| 背景卡 | 名称+⚡使用 一体按钮 | 同职业样式 |

**无主动技能时**：特性区只显示特性名纯文字（16px），无按钮。

**消耗信息**：放在按钮 `title` 悬浮提示中，不占按钮空间。

**禁用态**：冷却中/资源不足时按钮整体半透明（`opacity: 0.4`）。

### 映射地 — 快捷栏

从原生卡片**安装**过来的快捷方式：

- 槽位数量按页面宽度自适应
- 每个槽位显示：图标、技能名称、消耗符号、动作类型标签（动/附/反/特）
- 空槽位可安装新技能（仅编辑模式）
- 当前有架势激活时，显示带 X 的架势标签，点 X 结束架势

**两条路径点按钮后都走同一个确认弹窗。**

## 二、确认弹窗（唯一的中枢）

弹窗打开后，玩家看到三样东西：

### 1. 资源消耗区

根据卡片类型不同，显示不同的控件：

| 消耗类型 | 控件 | 说明 |
|---------|------|------|
| 固定法术位 | 文字显示 | 显示环位和剩余数量 |
| 自由法术位 | 下拉选环位 | 1环到最大可用环位 |
| 充能/职业资源 | 加减按钮 | 选使用次数，上限为当前可用量 |
| 无消耗 | 文字"无消耗" | 不显示控件 |

### 2. 效果预览列表

- 每个效果一行，带颜色标记和类型标签
- 多效果卡片全部列出
- 按消耗倍数缩放显示（×2、×3 等）

### 3. 生物选择（仅变身/召唤卡片）

- 卡片需要选生物且没预设时，弹窗出现下拉框
- 德鲁伊变身按等级限制可选生物的CR（1级=CR 1/3，每3级+1）
- 必须选了生物才能点确认

### 确认按钮

显示「确认使用 (n)」，n 是使用次数。召唤星体替身时显示「召唤替身」。

---

## 三、确认后的执行流程

### 步骤 1：资源预检
资源不够 → 直接显示红色「释放失败」结果，不往下走。

### 步骤 2：扣资源
法术位 / 自由法术位（向上搜索可用环位）/ 职业资源 / 物品充能，实际扣减。

### 步骤 3：荒野变形预检
荒野变形次数用完 → 阻止执行。

### 步骤 4：逐个执行效果

| 效果类型 | 行为 |
|---------|------|
| 攻击加成 | 加入命中加值，附带额外伤害骰，资源投放越多效果越好，模拟投掷计算结果 |
| 法术 | 执行法术本体 + 所有子效果（能量输出/治疗/变身/召唤/恢复法术位/消耗法术位恢复充能/攻击加成/自定义逻辑） |
| 能量输出 | 覆盖龙息或豁免判定的能量攻击，分自身豁免/固定豁免，有距离和形态，掷骰计算结果 |
| 临时BUFF | 安装到角色；架势类设置当前架势状态，按环位/次数缩放；本质上可连接所有被动BUFF，但带有时间效应 |
| 变身 | 安装变身BUFF（结构化持续时间） |
| 召唤 | 添加召唤生物到列表；星体替身会分裂HP；普通召唤可能消耗金币/HP |
| 随机表 | 掷骰子或抽扑克牌，命中条目后递归执行子效果 |
| 治疗 | 分三种模式：按骰子掷、按等级/重量固定值、直接回满 |
| 自定义逻辑 | 覆盖无法数值化的功能，重点是消耗资源 |
| 消耗法术位恢复充能 | 消耗资源回复对应环位法术位，恢复物品充能；长短休可回复环位，类似奥术回想，短休恢复时法术等级环位自由分配 |

### 步骤 5：架势互斥
新架势自动替换旧架势（旧BUFF移除，状态清除）。

### 步骤 6：触发3D骰子动画
所有掷骰数据发送到动画层（BottomNav → ThreeDiceOverlay）。

### 步骤 7：显示结果页面
列出所有效果执行结果文字。

## 四、中途打断（弹窗内二次确认）

某些效果执行到一半会暂停弹窗，等玩家选择：

| 触发条件 | 弹窗内容 | 选"否"的后果 |
|---------|---------|------------|
| 星体替身召唤 | "是否确认召唤？" | 不召唤，资源退回 |
| 自定义逻辑治疗超最大HP | "是否继续？" | 不治疗，资源退回 |
| 能力治疗效果 | "是否应用治疗？" | 不治疗，资源退回 |

**特点**：资源先预扣，等玩家确认后才正式生效。选"否"则效果不执行、资源全额退回。

**伤害不需要手动输入**：所有伤害通过掷骰计算得出，由子引擎自动处理。

## 五、系统自动行为（被动触发）

### 短休息时
- 重置短休冷却的主动技能
- 清理到期的临时BUFF（"持续到短休"的BUFF自动消失）
- 恢复护盾和护盾池

### 长休息时
- 重置所有冷却的主动技能（短休 + 长休）
- 恢复所有法术位到最大值
- 恢复物品充能（长休恢复类）
- 清理到期的临时BUFF（包括"到黎明"的）
- 恢复护盾和护盾池

### 架势切换时
- 新架势自动替换旧架势（旧BUFF移除，状态清除）
- 快捷栏自动更新显示新架势名称

## 六、设计原则：所有入口共用同一套逻辑

**所有入口（原生卡片、快捷栏、装备、专长、种族）必须走同一个确认弹窗（AbilityUseModal），执行同一条管线。** 不允许任何入口绕过确认弹窗直接执行。

### 当前违反此原则的已知问题

| 问题 | 现状 | 应改为 |
|------|------|--------|
| 装备入口 | 闪光按钮不走确认弹窗，直接 alert 显示结果，参数顺序有误 | 走 AbilityUseModal 确认弹窗 |
| 专长/种族入口 | 只传了第一个效果，多效果卡片丢后续效果 | 传完整效果列表，与快捷栏/原生卡片一致 |

---

## 七、数据流概览

```
原生卡片 / 快捷栏
    ↓ 点击"使用"
确认弹窗（AbilityUseModal）
    ↓ 选择资源 + 生物（如需）
    ↓ 点确认
扣资源 → 执行效果 → 3D骰子动画 → 结果页面
    ↓ 点关闭
数据保存（patch 写回角色）
```
