# 生物库改造设计 — 荒野变形完善

> 日期：2026-09-01
> 状态：设计中，待用户审核
> 核心场景：德鲁伊荒野变形

---

## 一、问题背景

当前生物库系统存在以下问题：

1. **三个已知 Bug**：
   - 召唤生物的 HP 默认只有 10（数据格式不匹配）
   - 变身状态栏显示生物 ID 而不是名字（联网模式下）
   - 联网模式下生物库数据不会自动加载（必须手动访问生物库页面）

2. **编辑器不完整**：生物数据模型里预留了易伤、状态免疫、天生武器的字段，但编辑器里没有编辑入口。反应、传奇动作、法术区域则连数据字段都不存在，需要一并新增。

3. **天生武器不参与战斗**：变身后生物的爪击、啮咬等天生武器只存在数据里，不会出现在角色的战斗手段中，无法用来攻击。

4. **荒野变形次数不自动扣减**：系统已经定义了荒野变形的资源计数器（按德鲁伊等级自动算上限、短休恢复），但变身时不会自动扣次数，玩家只能手动点减号。

5. **生物法术无法使用**：有些生物本身会施法（如树妖、某些龙类），但生物数据里没有法术区域，变身后也无法使用生物的法术。

6. **生物选择弹窗类型筛选不全**：14 种生物类型只列了 5 种。

---

## 二、设计目标

- 修复三个已知 Bug，确保生物库数据在各模式下正常工作
- 补全生物编辑器，DM 可以配置完整的生物数据
- 变身后天生武器自动出现在战斗手段中，可以投骰攻击
- 变身时自动扣减荒野变形次数
- 变身后生物的法术作为战斗手段按钮出现，可以释放
- 变身后的状态免疫完全替换角色的（符合 D&D 规则）

## 三、Bug 修复

### 3.1 召唤生物 HP 只有 10

**问题**：AbilityUseModal 在读取召唤生物 HP 时，期望的是对象格式（如 `{ formula, max }`），但生物库存储的是数字或公式字符串（如 `45` 或 `"6d8+18"`）。格式不匹配导致回退到默认 10 HP。

**修复**：让召唤 HP 读取逻辑兼容生物库的实际存储格式。如果 `creature.hp` 是数字直接用，如果是字符串用现有的 `parseHpFormula()` 转成平均值。

### 3.2 变身状态栏显示 ID 而不是名字

**问题**：BuffListItem 在显示"变身（XX生物）"时，直接读 `localStorage['dnd_creature_library']` 原始数据，跳过了正式的数据读取接口。联网模式下本地存储为空，名字无法解析。

**修复**：改为通过正式的数据读取接口（`getCreatureById()`）获取生物名字。需要确保在需要时已加载生物库数据。

### 3.3 联网模式下生物库数据不自动加载

**问题**：`loadCreatureLibraryFromSupabase()` 只在生物库管理页面被调用。其他消费者（BUFF 计算器、生物选择弹窗、AbilityUseModal）在 Supabase 模式下看到的是空列表。

**修复**：在应用启动时或角色卡加载时，自动调用一次 `loadCreatureLibraryFromSupabase()`。或者将生物库数据纳入全局数据预加载流程。

## 四、补全生物编辑器

### 4.1 新增编辑区域

在现有编辑器（CreatureLibraryManager）中，在特性/动作区域附近新增以下编辑入口：

**易伤（vulnerabilities）：**（字段已有，补 UI）
- 文字输入区域，逗号分隔（和现有抗性/免疫的输入方式一致）
- 例如："火, 冰霜"

**状态免疫（conditionImmunities）：**（字段已有，补 UI）
- 文字输入区域，逗号分隔
- 例如："魅惑, 恐慌, 擒抱"

**天生武器（naturalWeapons）：**（字段已有，补 UI）
- 列表，每行一个天生武器：
  - 名字输入框（如"爪击"、"啮咬"）
  - 攻击加值输入框（数字，如 5）
  - 伤害输入框（文字，如"2d6+3 挥砍"）
  - 删除按钮
- 底部"添加天生武器"按钮

**反应动作（reactions）：**（新增字段）
- 列表，每行一个反应：
  - 名字输入框
  - 描述文字框
  - 删除按钮
- 底部"添加反应"按钮

**传奇动作（legendaryActions）：**（新增字段）
- 传奇动作点数（数字输入框）
- 列表，每行一个传奇动作：
  - 名字输入框
  - 描述文字框
  - 消耗点数输入框
  - 删除按钮
- 底部"添加传奇动作"按钮

### 4.2 法术区域（新增字段）

以下字段在当前生物数据模型中不存在，需要新增到数据模型和默认值中：

**施法属性（spellcastingAbility）：**
- 下拉菜单：智力 / 感知 / 魅力 / 无

**法术豁免 DC（spellSaveDC）：**
- 数字输入框

**法术攻击加值（spellAttackBonus）：**
- 数字输入框

**法术列表（spells）：**
- 列表，每行一个法术条目：
  - 法术名称输入框
  - 释放方式下拉：随意 / 每天 N 次 / 需要法术位
  - 如果是"每天 N 次"，显示一个数字输入框（次数）
  - 如果是"需要法术位"，显示一个环位下拉（1-9 环）
  - 法术描述文字框（可选）
  - 删除按钮
- 底部"添加法术"按钮

### 4.3 现有区域不变

- 基本信息（名字/体型/类型/CR）：不变
- 六维属性：不变
- HP / 命中骰 / AC：不变
- 五种速度：不变
- 抗性 / 免疫：不变
- 特性（带效果编辑器）：不变
- 动作（名字 + 描述）：不变

## 五、天生武器接入战斗计算

### 5.1 数据来源

变身激活时，计算管线从生物库读取该生物的天生武器列表（`naturalWeapons`），通过 `buffStats.creatureTransform` 暴露给 UI 层。

### 5.2 战斗手段注入

角色的战斗手段（`combatMeans`）是存储在角色数据中的持久数组。变身后不需要修改这个数组，而是在 UI 渲染时追加临时条目：

当角色处于变身状态且目标生物有天生武器时，在 CombatStatus 的战斗手段列表中：

- 在持久战斗手段之后，追加一个"天生武器"分区
- 生物的每个天生武器渲染为一个临时战斗手段行：
  - **名字**：生物的天生武器名字（如"爪击"）
  - **类型**：标记为"天生武器"（`isNatural: true`）
  - **攻击加值**：使用生物数据中的 `attackBonus`（生物已算好的值，包含属性加值和熟练加值）
  - **伤害骰**：使用生物数据中的 `damage` 字符串（如"2d6+3 挥砍"），解析出骰子和伤害类型
  - **作用域**：自动匹配"天生武器"作用域（已有的 `natural_weapon` scope）
- 临时条目带有明显的视觉区分（如半透明边框或"变身"标签），表示它们来自变身

### 5.3 点击天生武器攻击

点击临时战斗手段行 → 弹出释放弹窗（AbilityUseModal）→ 投骰：
- 攻击骰：d20 + 生物的 `attackBonus`
- 伤害骰：按生物的 `damage` 字符串投骰（如"2d6+3"）
- 命中/伤害的条件加值（如 BUFF 编辑器里配置的"对某类生物+X"）正常生效，因为作用域已经是 `natural_weapon`

### 5.4 变身结束

- 变身 BUFF 移除或过期后，临时战斗手段自动消失
- 角色恢复正常的武器列表

### 5.5 与现有系统的关系

- 天生武器不占用背包格子
- 天生武器和角色的装备武器并列显示，玩家可以选着用哪个
- 已有的"天生武器"效果作用域（效果编辑器里的 scope）天然支持——给天生武器加 BUFF 的逻辑已经存在

## 六、荒野变形次数自动扣减

### 6.1 现状

系统已经定义好了荒野变形的资源规则：
- 资源键：`wild_shape`
- 次数表：1-8 级每天 2 次，9-17 级 3 次，18+ 级 4 次
- 恢复方式：短休恢复
- 状态栏已有计数器显示（当前/上限）

**但是**：变身时使用的是另一个键 `wild_shape_uses`（写在 BUFF 效果上），和计数器 `wild_shape` 不通。

### 6.2 修复方案

当玩家创建或激活一个变身 BUFF（`creature_transform` 类型）且该 BUFF 标记了荒野变形模式（`wildShapeMode: true`）时：

1. 在角色的 `classResources` 中找到 `resourceKey === 'wild_shape'` 的条目
2. 检查 `current > 0`
3. 将 `current` 减 1
4. 保存角色数据

触发位置：在 BUFF 被添加到角色时（CombatStatus 的 BUFF 创建/激活逻辑中），检测到 creature_transform + wildShapeMode 后执行扣减。

### 6.3 资源不足时的处理

- 如果 `current <= 0`，阻止变身，提示"荒野变形次数已用完"
- DM 可以通过手动调整计数器来覆盖这个限制
- 如果角色没有德鲁伊等级（没有 wild_shape 资源条目），不扣减，也不阻止（可能是其他来源的变身）

### 6.4 对现有系统的影响

- 不改变资源计数器的显示方式（已有 UI）
- 不改变短休/长休恢复逻辑（已有）
- 只需要在变身激活时加一步扣减逻辑

## 七、生物法术作为战斗手段

### 7.1 数据来源

变身激活时，计算管线从生物库读取该生物的法术数据：
- `spellcastingAbility`（施法属性）
- `spellSaveDC`（法术豁免 DC）
- `spellAttackBonus`（法术攻击加值）
- `spells`（法术列表）

通过 `buffStats.creatureTransform` 暴露给 UI 层。

### 7.2 战斗手段注入

与天生武器类似，生物法术在 UI 层作为临时条目渲染，不修改角色持久数据：

当角色处于变身状态且目标生物有法术列表时，在 CombatStatus 的战斗区域中：

- 在天生武器分区之后，追加一个"生物法术"分区
- 生物的每个法术渲染为一个临时按钮：
  - **名字**：法术名称
  - **豁免 DC**：使用生物的 `spellSaveDC`（不用角色自身的）
  - **攻击加值**：使用生物的 `spellAttackBonus`（不用角色自身的）
  - **释放方式**：
    - "随意"：不限次数，直接释放
    - "每天 N 次"：追踪已用次数（存在 CombatStatus 的临时状态中，变身结束重置）
    - "需要法术位"：消耗角色的对应环位法术位
  - 临时按钮带有视觉区分（与天生武器分区类似的"变身"标签）

### 7.3 释放流程

点击法术按钮 → 弹出释放弹窗（AbilityUseModal）→ 投骰（攻击骰或豁免）→ 记录结果

- 攻击类法术：使用生物的法术攻击加值投 d20
- 豁免类法术：使用生物的法术豁免 DC
- 伤害/效果：按法术描述投骰

### 7.4 变身结束

- 变身 BUFF 移除或过期后，临时法术按钮消失
- "每天 N 次"的已用次数追踪也一并清除

## 八、状态免疫完全替换

### 8.1 现状

计算管线在变身时已经替换了抗性和免疫列表，但状态免疫（`conditionImmunities`）虽然存了数据，注释写着"先简单记录"，没有实际生效。

### 8.2 修复方案

在 `computeBuffStats()` 的变身处理中，现有代码已经对生物的抗性、免疫、易伤做了"清空 + 替换"处理。状态免疫应该用同样的模式：

- 找到现有的"状态免疫也合并"代码块（当前是空的，只有注释"先简单记录"）
- 填充逻辑：清空已收集的 `conditionImmunities` Set，然后将生物的状态免疫列表写入
- 后续代码已经会将 `conditionImmunities` Set 展开到 `buffStats.conditionImmunities` 输出中，不需要额外改动
- UI 层已经读取 `buffStats.conditionImmunities` 来过滤角色身上的状态效果

### 8.3 设计决策

- 完全替换，不叠加（用户确认：符合 D&D 规则）
- 变身后角色原本的状态免疫全部失效，以生物的为准
- 变身结束后恢复角色自身的状态免疫
