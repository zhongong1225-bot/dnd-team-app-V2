# 角色页「档案」标签页重组设计

- 日期：2026-09-14
- 状态：待用户审阅
- 范围：仅 `src/pages/CharacterSheet.jsx` 的 `#sheet-profile` 区块及其子组件；顶栏与其他标签页不动

## 1. 背景与问题

现状档案页是一张大卡片装所有内容，问题清单：

1. **层级扁平**：整页只有一个外框，内部仅靠两个小金字标题（外观 / 基础、人物背景故事）分区，字段标签、分区标题、页面标题三级字号字重接近，看不出层级。
2. **右栏死空间**：头像上传框固定占 500px 宽右栏，未上传时半页空白；上传后也与内容无比例关系。
3. **控件语言混杂**：下划线输入框（代号/名字/外观字段）、盒装下拉（体型）、带铅笔的胶囊按钮（种族/背景）、芯片下拉（属性加值）、统一卡片（种族特性）、虚线占位框（背景特性）、大文本域（故事）七种样式并存。
4. **全时可编辑**：所有字段任何时候都是输入控件，视觉上永远"在编辑中"，噪声大。
5. **身份重复**：顶栏已有角色名，档案页又用超大输入框重复一次。

## 2. 目标与非目标

目标：

- 档案页分成层级清晰的分区：头部条 / 基础档案 / 种族与背景 / 肖像 / 背景故事。
- 默认只读，每个分区一个「编辑」按钮进入编辑态。
- 头像成为视觉主角：宽屏右栏通高，肖像与背景故事合占整页一半宽，栏内比例肖像:故事 = 2:1。
- 窄屏单栏回退，顺序固定。

非目标：

- 不改顶栏、不改其他标签页、不改种族特性卡的统一卡片样式、不改生物模版区块（`CreatureSimpleBlock`）、不改头像上传的存储逻辑（只换位置与尺寸）。

## 3. 页面结构

### 3.1 宽屏（≥ lg）

`#sheet-profile` 内部改为两栏等宽网格（`lg:grid-cols-2 gap-3`），两栏 stretch 等高：

**左栏（内容）**，自上而下：

1. **头部条**：角色名（20px 粗）+ 代号（11px 灰蓝）+ 种族芯片 + 背景芯片 + 右侧「编辑」。
2. **基础档案分区**：9 个字段三列只读网格（年龄/阵营/瞳色/身高/肤色/体重/发色/体型/移速），下方感官芯片行。
3. **种族与背景分区**：属性加值芯片（+2 智力 等）+ 种族特性卡列表（沿用现有统一卡片）+ 背景特性占位卡。

**右栏（视觉）**，`flex column`：

1. **肖像面板** `flex: 2`：圆角 8、边框 `#34455f`、`object-fit: cover`；无图时居中"上传头像"占位且整块可点；底部悬浮条（`rgba(10,16,26,0.72)`）写"更换头像"。
2. **背景故事分区** `flex: 1`：只读散文，超出高度区内纵向滚动（4px 细滚动条）。

### 3.2 窄屏（< lg）

单栏纵向，顺序：头部条 → 肖像（全宽、`max-height: 320px`）→ 基础档案 → 种族与背景 → 背景故事。分区样式不变，右栏 2:1 比例约束不适用。

## 4. 只读 / 编辑两态

- 只读态：纯文字值与芯片，无下划线、无输入框底纹；空值显示 `—`。
- 每个分区右上一个胶囊按钮：只读态写「编辑」，编辑态写「完成」。
- 编辑态内复用现有可编辑控件与现有持久化时机（blur / change 即存），不新建草稿缓冲；「完成」仅退出编辑态。不做回滚式「取消」——回滚由模组快照承担，避免半保存状态把 persist 路径复杂化。
- 头部条的编辑态控制角色名与代号（复用现有 `NameInput` / `editingCodename` 逻辑）。
- 基础档案编辑态：外观全部字段的输入框（含体型/移速/感官）。
- 种族与背景编辑态：种族/背景选择与铅笔入口、属性加值下拉（复用 `RaceBackgroundInline` 现有控件与 buff 编辑器弹窗接线）。
- 背景故事编辑态：现有文本域组件。
- `canEdit === false` 时所有「编辑」按钮隐藏，页面纯只读。

## 5. 视觉规范

| 元素 | 规格 |
|------|------|
| 分区卡 | 底 `#1a2332`、边框 1px `#2a3a4e`、圆角 8px、内边距 10px |
| 分区标题 | 11px、`#c79a42`、字距 1px、字重 600 |
| 编辑/完成按钮 | 11px 胶囊、边框 `rgba(199,154,66,0.6)`、字 `#c79a42`、hover 底 `rgba(199,154,66,0.08)` |
| 字段标签 | 10px `#66788c` |
| 字段值 | 13px `#dfe6ee` |
| 芯片 | 11px、边框 `#34455f`、圆角 999px、字 `#aabbcc`、内边距 1px 8px |
| 故事正文 | 13px、行高 1.7、`#93a3b5` |
| 肖像悬浮条 | 11px `#aabbcc`、底 `rgba(10,16,26,0.72)` |

层级靠"分区卡 + 留白"表达，不再给单个字段加框或下划线（只读态）。

## 6. 组件拆分

- `ProfileIdentityBar`（新）：头部条，props = char / canEdit / 编辑态开关 / persist。
- `ProfileSection`（新）：分区外壳 = 标题 + 右上按钮 + 内容槽；只负责两态按钮与卡片样式。
- `AppearanceReadGrid`（新）：9 字段只读网格 + 感官芯片行。
- `PortraitPanel`（新）：肖像面板 + 悬浮条 + 上传接线（复用现有上传逻辑）。
- `RaceBackgroundInline` 拆渲染子集：基础档案编辑态取体型/移速/感官；种族与背景分区取种族/背景/加值槽；`raceBuffEditorOpen` 等弹窗接线保持不变。
- `CharacterSheet.jsx` 的 `#sheet-profile` 只保留两栏骨架与编辑态状态（`editingSection: null | 'identity' | 'basic' | 'racebg' | 'story'`）。

## 7. 验证

1. `npx vite build` 通过。
2. 浏览器宽屏截图：两栏等宽、右栏肖像:故事 ≈ 2:1、分区标题/字段层级清晰。
3. 浏览器窄屏截图：单栏顺序正确、肖像限高 320px。
4. 交互往返：每个分区进入编辑态改一个值→完成→刷新后值仍在；名字修改、故事编辑、头像上传入口可点。
5. 回归：装备区、BUFF 区截图确认未受影响；`canEdit=false`（非管理员视角）无编辑按钮。

## 8. 风险

- `CharacterSheet.jsx` 已超 4000 行，本次改动集中在 `#sheet-profile` 一段，不碰其他 section。
- `RaceBackgroundInline` 拆分时需保留 buff 编辑器弹窗与属性加值槽的既有行为（近期刚恢复的 +2/+1 分配槽）。
- 并发会话可能同时改 CharacterSheet.jsx：编辑前先重读目标区域。
