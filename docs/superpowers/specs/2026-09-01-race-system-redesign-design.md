# 种族系统改造设计 — 让种族定义直接生效

> 日期：2026-09-01
> 状态：设计中，待用户审核
> 方案：方案一（专用加值槽）

---

## 一、问题背景

当前种族系统存在以下问题：

1. **种族定义的速度和暗视不参与计算**：种族编辑器里配置了五种速度和暗视距离，但这些数据只用于展示，不会自动影响角色数值。
2. **属性加值需要手动重复填写**：种族定义里没有属性加值字段。每次选种族，玩家要在角色卡的"基础信息"里手动填六个属性的加值数字。同一个种族的不同角色要重复填写。
3. **体型不参与任何功能**：体型存了但没有下游消费者。
4. **数据流断裂**：种族定义的数据和角色实际生效的数据之间没有自动连接，需要玩家手动桥接。

---

## 二、设计目标

- 选种族时，种族定义的速度、暗视、体型、属性加值自动应用到角色
- 种族基础值是天生属性，不可覆盖（后天变化走 BUFF）
- 属性加值采用自由选择模式：种族定义加值槽，玩家分配属性
- 旧角色数据自动迁移

---

## 三、数据结构变化

### 3.1 种族定义新增字段

在种族定义（raceModel）中新增：

```
abilityScoreBonuses: [{ amount: number }]
```

- 每个元素是一个"加值槽"，只有一个数字（正数或负数）
- 例如精灵：`[{ amount: 2 }, { amount: 1 }]`
- DM 在种族编辑器中可以随意加减槽、改数字
- 默认模板：两个槽，+2 和 +1

子种族也各自有独立的 `abilityScoreBonuses` 字段。

### 3.2 角色卡种族信息变化

**旧结构（raceBaseInfo）：**
- `speed`: 单个数字（步行速度）
- `size`: 体型字符串
- `vision`: `{ type, range }` 或 null
- `abilityScoreIncrease`: `{ str, dex, con, int, wis, cha }` 六个数字

**新结构（raceBaseInfo 重构）：**
- `speed`: 保留旧字段用于向后兼容，新数据从种族定义读取
- `size`: 保留旧字段，新数据从种族定义读取
- `vision`: 保留旧字段，新数据从种族定义读取
- `abilityScoreIncrease`: **废弃**，替换为 ↓
- `asiAssignments`: `[{ source: string, ability: string }]`
  - 每个元素表示一个加值槽分配到了哪个属性
  - `source` 为 `'race'`（父种族槽）或 `'subrace'`（子种族槽）
  - 同一 source 内，数组中的位置对应该种族的加值槽列表顺序
  - 例如：父种族有两个槽（+2, +1），子种族有一个槽（+1）
    - `[{ source: 'race', ability: 'dex' }, { source: 'race', ability: 'wis' }, { source: 'subrace', ability: 'con' }]`
    - 含义：种族+2→敏捷，种族+1→感知，子种族+1→体质
  - 切换子种族时：只清空 source='subrace' 的条目，父种族分配保留
  - 切换父种族时：清空所有条目

### 3.3 旧字段处理

旧字段（speed、size、vision、abilityScoreIncrease）保留在存储结构中用于向后兼容，但 UI 不再显示编辑入口。新代码从种族定义读取数据，忽略这些旧字段（迁移逻辑除外）。

## 四、种族编辑器变化

### 4.1 新增"属性加值"区域

在种族编辑器（RaceEditorForm）中，速度/暗视区域附近新增：

- 标题："属性加值"
- 列表，每行一个加值槽：
  - 一个数字输入框（加值多少，支持正负数）
  - 一个删除按钮
- 底部一个"添加加值槽"按钮
- 默认值：两个槽，+2 和 +1

### 4.2 子种族编辑

子种族编辑器中也有同样的"属性加值"区域，独立配置。

### 4.3 现有区域不变

- 速度（五种速度输入）：不变
- 暗视（数字输入）：不变
- 体型（多选 + 默认）：不变
- 特性（效果编辑器卡片）：不变
- 参考表格：不变

---

## 五、角色卡种族区域变化

### 5.1 选种族后的自动行为

玩家从种族列表选一个种族后，系统自动：

1. 从种族定义读取速度（五种）、暗视距离、默认体型
2. 合并父种族和子种族的加值槽列表，展示分配界面
3. 如果是切换父种族：清空所有属性加值分配，玩家重新选
4. 如果是切换子种族：只清空子种族的加值分配，父种族的分配保留

### 5.2 基础信息面板新外观

**只读展示区（灰色不可编辑）：**
- **体型**：显示种族默认体型
- **速度**：显示五种速度值（步行/攀爬/游泳/飞行/挖掘），无值的显示为 0 或"—"
- **特殊感官**：显示种族给的感官类型和距离（如"黑暗视觉 60 尺"）

**可操作区：**
- **属性加值分配**：
  - 分组显示，父种族的槽一组（标题"种族加值"），子种族的槽一组（标题"子种族加值"）
  - 每行对应一个加值槽，格式："+X → [下拉菜单选属性]"
  - 下拉菜单选项：力量/敏捷/体质/智力/感知/魅力
  - 已被其他槽选中的属性在下拉菜单中变灰或隐藏，防止重复选择

### 5.3 切换种族

- 所有只读值自动更新为新种族的数据
- 切换父种族：所有属性加值分配清空，玩家重新选
- 切换子种族：只清空子种族的加值分配，父种族的分配保留
- 旧的覆盖值不保留（设计意图：种族基础值不可覆盖）

### 5.4 手动效果补丁保留

角色卡上的"种族手动效果补丁"（raceBuffPatch）保留不变。这给 DM/玩家一个额外通道，可以添加种族相关的特殊效果。

## 六、计算管线集成

### 6.1 数据来源变化

**改前：** cardAdapter 从 raceBaseInfo（玩家手动填的值）生成效果
**改后：** cardAdapter 从种族定义自动读取数据，结合玩家的 ASI 分配，生成效果

### 6.2 效果生成规则

1. **速度**：
   - 读取种族定义的五种速度（步行/攀爬/游泳/飞行/挖掘）
   - 生成一个 base_speed_increment 效果，值为对象格式：`{ walk, climb, swim, fly }`
   - 步行速度存差值（减去默认的 30 尺）：种族给 30 尺 → walk: 0（不写），25 尺 → walk: -5，35 尺 → walk: 5
   - 其他速度存绝对值（因为默认是 0）：种族给游泳 30 尺 → swim: 30
   - 如果所有速度都是默认值（walk=30，其余=0），不生成效果
   - 注意：现有管线只追踪 walk/fly/swim/climb 四种速度，挖掘速度（burrow）虽然存储和展示，但不参与数值计算（这是既有限制，不在本次改造范围内）
   - 现有的计算管线已经支持这种对象格式（parseBaseSpeedIncrement），不需要改管线

2. **暗视/特殊感官**：
   - 读取种族定义的 darkvision 值
   - 如有值 → 生成 special_senses 效果（类型: darkvision, 距离: 该值）

3. **属性加值**：
   - 分别读取父种族和子种族的加值槽列表
   - 读取玩家的 asiAssignments，按 source 分组匹配
   - source='race' 的条目按位置对应父种族的加值槽
   - source='subrace' 的条目按位置对应子种族的加值槽
   - 对每个已分配的槽，生成 ability_score_uncapped 效果
   - 例如：父种族槽为 [+2, +1]，asiAssignments 中 source='race' 的两条分别分配到敏捷和感知
     → 生成 `{ ability: 'dex', value: 2 }` 和 `{ ability: 'wis', value: 1 }` 两个 uncapped 效果
   - 仍受 20 点上限限制（除非有专长突破上限）

### 6.3 对现有管线的影响

- BUFF 计算管线本身不变（computeBuffStats 的 pass 顺序不变）
- 只是输入源从"手动填的值"变为"种族定义自动读取 + 玩家分配"
- 效果类型（base_speed_increment、special_senses、ability_score_uncapped）不变

## 七、旧数据兼容

### 7.1 迁移逻辑

当加载一个旧角色时（有 raceBaseInfo 但没有 asiAssignments）：

1. **属性加值迁移**：
   - 读取旧的 abilityScoreIncrease（六个属性各一个数字）
   - 找出非零值的属性，按数值从大到小排列
   - 读取种族定义的加值槽，按数值从大到小排列
   - 尝试一一匹配：如果旧数据的非零值集合与种族定义的加值槽集合一致，自动生成 source='race' 的分配条目
   - 如果匹配不上（种族定义改了、或旧数据有异常值），清空分配，让玩家重新选

2. **速度和暗视**：
   - 旧的手动值丢弃
   - 新值完全从种族定义读取
   - 如果旧角色手动改过速度（与种族定义不同），这个覆盖丢失（符合设计意图）

3. **没选种族的旧角色**：
   - 不受影响
   - 种族区域保持空白
   - 等玩家选了种族后自动填充

4. **旧格式种族（遗留的九个预设种族）**：
   - 这些旧种族的特性是纯文字，没有加值槽、没有速度定义
   - 如果角色还用的是旧种族格式，种族区域只显示名字
   - 不产生任何数值效果
   - 系统提示需要先在种族编辑器里补全数据

### 7.2 迁移时机

迁移在角色加载时自动执行（lazy migration），不需要批量转换脚本。

## 十一、设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 属性加值模型 | 自由选择（加值槽 + 下拉分配） | 用户选择，符合 2024 规则灵活性 |
| 种族基础值可覆盖？ | 不可覆盖，只读 | 用户明确：种族给的是天生的，后天变化走 BUFF |
| 速度覆盖粒度 | 五种速度都从种族定义读取 | 与"不可覆盖"一致 |
| 体型是否参与计算 | 否，纯展示 | 用户选择，当前无下游消费者 |
| 实现方案 | 方案一：专用加值槽 | 用户选择，概念清晰，不复用选择型 BUFF |
| 旧数据迁移 | 自动推断 + 清空不匹配的 | 平衡自动化和准确性 |
| ASI 分配存储 | 按来源分组（source 标记 + 位置映射） | 切换子种族时保留父种族分配，避免扁平索引错位 |
| 挖掘速度 | 存储和展示，不参与计算 | 现有管线不支持 burrow，不在本次范围内 |
