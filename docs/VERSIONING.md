# 版本管理与部署规范

> 最后更新：2026-09-02

---

## 一、版本号规则

本项目采用 **语义化版本**（Semantic Versioning）：`v主版本.次版本.修订号`

| 部分 | 含义 | 何时递增 |
|------|------|---------|
| **主版本** (Major) | 不兼容的 API 变更或架构重构 | 卡槽架构上线、存储格式大改 |
| **次版本** (Minor) | 向后兼容的新功能 | 新增职业/种族/生物库功能、UI 重构 |
| **修订号** (Patch) | 向后兼容的问题修复 | Bug 修复、性能优化、文案修正 |

**当前版本**：见 `src/config/version.js` 中的 `APP_VERSION`

## 二、版本递增时机

### 2.1 修订号递增（v3.0.1, v3.0.2...）

以下情况只递增修订号：
- 修复单个 Bug（如召唤 HP 读取错误）
- 修改文案或样式微调
- 性能优化（不影响功能）
- 修复浏览器兼容性

**示例**：
```
v3.0.0 → v3.0.1  修复成年银龙名字显示问题
v3.0.1 → v3.0.2  修复 JSON 解析报错
```

### 2.2 次版本递增（v3.1.0, v3.2.0...）

以下情况递增次版本：
- 完成一个完整的功能模块（如种族系统改造、生物库补全）
- UI 重大重构（如战斗手段卡片化）
- 新增数据模型（如新增背景数据表）
- 多个相关 Bug 修复 + 新功能

**示例**：
```
v3.0.0 → v3.1.0  完成种族系统改造（加值槽 + ASI 分配）
v3.1.0 → v3.2.0  完成生物库改造（天生武器 + 法术 + 变形次数）
```

### 2.3 主版本递增（v4.0.0）

以下情况递增主版本：
- 卡槽架构全面上线（Phase 2-5 完成）
- 存储格式不兼容变更
- 删除旧 API 或数据结构

**示例**：
```
v3.x.x → v4.0.0  卡槽架构取代旧存储结构
```

## 三、部署流程

### 3.1 开发阶段（不部署）

在本地开发时：
1. 代码改动后运行 `npm run dev` 测试
2. 提交 git commit，**不改版本号**
3. 可以多次 commit，累积到一个阶段性成果后再部署

**原则**：开发过程中的中间状态不需要部署，避免"不断说已部署但实际没更新"的问题。

### 3.2 部署触发条件

只有在以下情况才执行部署：

1. **用户明确说"部署"** — 如"现在部署"、"推到线上"
2. **完成一个阶段性目标** — 如种族系统改造全部完成并通过测试
3. **修复了紧急 Bug** — 需要立即上线的热修复

**禁止**：在没有用户确认的情况下自动部署。

### 3.3 部署前检查清单

部署前必须完成以下步骤：

```
□ 所有修改的代码已通过手动测试（在浏览器中验证功能）
□ 没有未解决的 console.error
□ git status 干净（没有未提交的改动，或已确认要部署的改动已暂存）
□ 版本号已递增（按上述规则）
□ CHANGELOG.md 已更新（记录本次部署的变更）
```

### 3.4 部署步骤

```bash
# 1. 递增版本号
# 编辑 src/config/version.js，修改 APP_VERSION

# 2. 更新 CHANGELOG.md
# 在顶部添加新版本号和变更说明

# 3. 提交版本变更
git add src/config/version.js CHANGELOG.md
git commit -m "chore: bump version to v3.x.x"

# 4. 推送到 Vercel
git push origin main   # 或对应分支

# 5. 等待 Vercel 构建完成
# 访问 https://dnd-team-app-v3.vercel.app 验证
```

### 3.5 部署后验证

部署完成后，必须执行以下验证：

1. **硬刷新浏览器**：`Ctrl+Shift+R`（Windows）或 `Cmd+Shift+R`（Mac）
2. **检查版本号**：在浏览器控制台输入 `window.APP_VERSION` 或直接看页面底部
3. **测试关键功能**：根据本次部署的内容，测试相关功能是否正常
4. **检查控制台**：确认没有新的报错

**如果验证失败**：
- 不要告诉用户"已部署成功"
- 说明具体问题（如"Vercel 构建失败"、"版本号未更新"）
- 给出下一步行动（如"正在排查构建日志"）

## 四、CHANGELOG 规范

每次部署前，在 `CHANGELOG.md` 顶部添加变更记录：

```markdown
## [v3.2.0] - 2026-09-02

### 新增
- 种族系统支持属性加值自由选择（加值槽模式）
- 生物库编辑器新增天生武器、法术、反应、传奇动作录入
- 变身后天生武器自动出现在战斗手段中

### 修复
- 修复召唤生物 HP 只有 10 的问题
- 修复变身状态栏显示生物 ID 而不是名字的问题
- 修复联网模式下生物库数据不自动加载的问题

### 改进
- 战斗手段卡片样式统一（天生武器/法术改为标准卡片）
- 生物选择弹窗类型筛选补全为 14 种
```

**格式要求**：
- 版本号用方括号 `[v3.2.0]`
- 日期用 ISO 格式 `2026-09-02`
- 分类：新增 / 修复 / 改进 / 移除
- 每条描述以动词开头，简洁明了

## 五、常见问题

### Q1：为什么我刷新页面后还是旧版本？

**原因**：浏览器缓存了旧的 JS/CSS 文件。

**解决**：
1. 硬刷新：`Ctrl+Shift+R`（Windows）或 `Cmd+Shift+R`（Mac）
2. 如果还不行，打开开发者工具 → Network 标签 → 勾选 "Disable cache" → 再刷新
3. 清除浏览器缓存后重新访问

**预防**：Vite 构建时会自动添加 hash，但某些 CDN 可能缓存时间过长。如果遇到持续缓存问题，可以在 Vercel 后台清除构建缓存。

### Q2：怎么确认部署真的成功了？

**方法**：
1. 访问 https://dnd-team-app-v3.vercel.app
2. 打开浏览器控制台，输入：
   ```js
   // 检查版本号
   import('/src/config/version.js').then(m => console.log(m.APP_VERSION))
   ```
   或者直接看页面底部的版本号显示
3. 查看 Vercel 部署日志：https://vercel.com/[your-project]/deployments

### Q3：部署后发现 Bug 怎么办？

**步骤**：
1. 立即告知用户问题详情
2. 在本地修复 Bug
3. 递增修订号（如 v3.2.0 → v3.2.1）
4. 更新 CHANGELOG.md
5. 重新部署

**不要**：隐瞒问题或假装没问题。

## 七、给 AI 助手的提醒

当你协助用户部署时：

1. **永远先问**："确认要部署吗？" — 不要自作主张
2. **部署前检查**：版本号是否已改、CHANGELOG 是否已更新、代码是否已测试
3. **部署后验证**：告诉用户如何硬刷新、如何检查版本号
4. **不要说谎**：如果部署失败或还没部署，如实告知，不要说"已部署好"
5. **记录变更**：每次部署后更新本文件的"版本历史"表格
